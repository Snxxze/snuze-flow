# SnuzeFlow i18n Translation Style Guide & Conventions

แนวทางปฏิบัติและข้อตกลงในการพัฒนาส่วนต่อประสานผู้ใช้งานหลายภาษา (i18n Localization) สำหรับทีมพัฒนา SnuzeFlow เพื่อควบคุมความเสถียรและทิศทางของ UX/UI ในระดับโปรดักชัน

---

## 1. กฎการแปลภาษา (Engineering Rules)

> [!IMPORTANT]
> **ห้าม Hardcode ภาษาที่สองลงใน String ภาษาหลักเด็ดขาด**  
> เช่น การใช้ `"email_label": "อีเมล (Email)"` ในไฟล์ภาษาไทย `th.json` ถือเป็นการทำผิดกติกา หากผู้ใช้งานเลือกสลับระบบเป็นภาษาไทย ข้อความภาษาอังกฤษคู่ขนานไม่ควรหลงเหลืออยู่ในระดับป้ายกำกับฟิลด์ (Labels)

- **ทำความสะอาดอยู่เสมอ:** ข้อความป้ายกำกับหรือคำสั่งหลักควรแสดงผลภาษาเดียวล้วนตามโครงสร้างภาษาที่เลือก (`th` หรือ `en`)
- **การใช้ตัวแปร:** หากต้องการใส่ตัวแปร ให้ครอบด้วยเครื่องหมายปีกกาคู่ตามมาตรฐาน i18next เช่น `{{count}} คำเชิญ` หรือ `อีก {{days}} วัน`
- **ไม่ผูก i18n กับ Base UI:** Reusable Components เช่น `button.tsx`, `input.tsx` ห้ามดึงค่าผ่าน `useTranslation()` ตรงๆ ให้ดึงค่าจาก Parent และส่งผ่าน Props หรือ Children เสมอ

## 2. วิธีจัดการคำศัพท์เฉพาะทางหรือศัพท์เทคนิค (Glossary Management)

สำหรับคำศัพท์ที่เป็นคำทับศัพท์ที่คุ้นเคยในภาษาอังกฤษ เช่น *Kanban Board*, *2FA*, *Timeline* หรือ *Dashboard* ให้ใช้แนวทางปฏิบัติข้อใดข้อหนึ่งดังนี้:

### แนวทาง A: นิยามชื่อคำศัพท์ที่เป็นมิตร (Friendly Translation)
พยายามหาคำไทยกลางที่เป็นมิตรและไม่ขัดต่อการรับรู้ของผู้ใช้งานทั่วไป เช่น:
- *Workspace* → พื้นที่ทำงาน
- *Task* → งาน
- *Assignee* → ผู้รับผิดชอบ

### แนวทาง B: แยก Key สำหรับคำศัพท์ย่อหรือทับศัพท์ (Term Glossary)
หากต้องการแสดงชื่ออังกฤษคู่ขนานจริงๆ เพื่อความเข้าใจของทีมพัฒนา ให้แยกออกไปทำ Component เช่น `TermWithGloss` หรือแสดงด้วย **Tooltip (ⓘ)** เมื่อนำเมาส์ไปชี้ แทนการฝังวงเล็บลงไปใน String ตรงๆ:

```tsx
// ตัวอย่าง Component ที่ต้องการอธิบายเพิ่ม
<div className="flex items-center space-x-1">
  <span>{t('auth.two_factor_auth')}</span>
  <Tooltip content="2FA" />
</div>
```

## 3. การลินต์ตรวจสอบข้อความแปลอัตโนมัติ (Automated Lints)

เพื่อป้องกันการนำคำภาษาอังกฤษในวงเล็บกลับมาในไฟล์ภาษาไทย นักพัฒนาสามารถสั่งรัน Linter สแกนหาคำแปลภาษาไทยที่ผิดรูปแบบผ่านคำสั่ง:

```bash
npm run lint:locales
```

สคริปต์นี้จะสแกนหา pattern `\(.*[a-zA-Z].*\)` ในทุกๆ ค่าคีย์ของ `th/translation.json` และสั่ง Fail Build อัตโนมัติในระบบ CI pipeline หากพบความผิดปกติ
